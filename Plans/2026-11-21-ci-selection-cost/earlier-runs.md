# Earlier PR validations and the full merge gate

An earlier PR push can use selected tests and still leave a later full validation to cover the final tree. We looked for this opportunity in actual CircleCI history. The rows below use the base and head recorded in each workflow's PR event. A real routing policy has to choose which run gets full validation **before** the next push is known.

## Observed traffic

CircleCI Insights returned 295 `iOS CI` workflows on sample branches between each PR's creation and merge within the October 1–November 22 UTC search window. Of those, 181 succeeded, 84 were canceled and 30 failed. We checked the pipeline event and PR number against GitHub and required both native test jobs to have succeeded. That left 162 successful full PR workflows. Of these, 91 ran the final PR SHA and 71 ran a different SHA. Those 71 came from 29 PRs. This count covers the retained window and successful runs of the named workflow. One PR opened before October 1. Failed, canceled, lightweight, manual, and post-merge runs receive no modeled savings here.

Each of the 71 workflows had a distinct base and head pair. The preview compared the merge base to the actual head. Sixteen pairs had a merge base different from the recorded base tip. Three would already take today's documentation shortcut, 44 defaulted to full, and 24 narrowed. Those 24 occurred on only seven PRs. Thirteen came from #416 and #422. These two PRs account for about half of the projected savings on earlier heads. [PR #416](https://github.com/kyleve/Stuff/pull/416) · [PR #422](https://github.com/kyleve/Stuff/pull/422)

## What could be captured

The 24 narrowed runs would save **25,803 credits** under the #555 calibration. Both #554 calibrations give a similar range, 24,533–25,450. All 24 shorten the modeled native gate under each calibration. The #555 estimate totals 1,998 seconds across those runs. This opportunity assumes perfect knowledge of the final head, covers successful runs only, and prices observed historical inputs at current worker timings. Historical billing is not the estimated saving. [Worker inputs](worker-inputs.md)

A draft-only policy would have identified zero of the 24. GitHub shows no conversions to draft or ready-for-review transitions for any of the seven merged PRs. A policy that triggers a separate full run on merge readiness needs an explicit signal and distinct coverage evidence. The final full gate still needs to pass on the exact tree eligible for reuse. [Merge reuse policy](https://github.com/kyleve/Stuff/blob/327b3f58e/Tools/ci_merge_validation.py)

For the fixture-cache comparison, 45 of the 68 otherwise-paid earlier runs have unchanged inputs. We counted a missing registry at either revision as a miss. Combining these with the 58 potential hits in the 100 landed examples gives 103 potential hits, worth **19,721 gross credits** in npm installation time under the #555 calibration. This combines one canonical final diff per PR with the 71 observed earlier runs. It assumes a warm cache, omits cache overhead, and does not include generator savings. The comparable selection figure with full final gates is 25,803. The difference, roughly 6,100 credits, is less than one additional full run. A trial measuring cache hit rate and lookup, restore and generation costs can narrow that comparison. [Fixture inputs](replay.md)
