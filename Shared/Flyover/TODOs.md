# Open issues

## P2s (Nice to have)
- fix [quick-win]: Preserve inspector shortcuts while the capture has focus — `Web/src/scripts/viewer.ts:224-240` returns for every key from a capture scroller. This blocks the documented `I` and bracket shortcuts as well as native arrow scrolling. A production Astro build at `63733b2cd` reproduced both failures in Chromium; the same shortcuts work from an inspector control. Limit the exemption to scrolling keys. Cover both focus locations while preserving native arrow behavior. (isolated agent review experiment 2026-10-26)
- fix [quick-win]: Separate unfiltered state from catalog group identity — `Web/src/scripts/panels.ts:98` uses `all` for both the unfiltered option and a catalog group with that valid ID. `Web/src/scripts/catalog.ts:83` then treats the selected group as unfiltered. `Sources/FlyoverGroupID.swift:5-8` permits this nonempty ID. Represent the unfiltered state separately and test a catalog containing both `all` and another group. At `63733b2cd`, the production manifest validator accepts this input and the actual catalog helper reproduces the collision; filtering the other group works. (isolated agent review experiment 2026-10-26)
- fix [needs-design]: Keep inspector controls visible beside the details drawer — the dock remains centered against the full viewport (`Web/src/styles/inspector.css:243-261`) before the details rule shifts it left (`:423-424`). At 800px with supported profile/state choices, a production Astro build at `63733b2cd` places the Previous button entirely offscreen and clips the State selector. Reserve the drawer's width or introduce a usable compact/scrollable layout for this range. Add browser bounds and interaction checks with details open and closed; 800px and 1200px provide failing and valid cases. (isolated agent review experiment 2026-10-26)
- convention [quick-win]: Preserve export errors for callers — `FlyoverWebExporter` replaces capture and output errors with `localizedDescription` (`Sources/FlyoverWebExporter.swift:114`, `:49`). `FlyoverExportError` retains only that string (`Sources/FlyoverExportError.swift:17-27`). Callers lose the original error type, domain, code, and attached context before the reporting boundary. Retain the underlying error alongside the export context, and derive display text when reporting it. Add a regression that injects a typed capture error and verifies that callers can recover it. Confirmed by source inspection at `63733b2cd`; no Swift runtime probe was run. (agent review experiment 2026-10-26)
- test [needs-design]: The engine is well covered but the interactive surfaces are not. **Fourteen** test files pin what the module computes (re-counted 2026-08-30 — the item said twelve, which undercounted `FlyoverContentLoadCoordinatorTests` and `FlyoverConnectorGeometryTests`; it was ten when filed) — the catalog, layout, model, canvas render and zoom plans, connector geometry, preview readiness, the serial content-load coordinator, and the stylesheet — while the UI it drives is verified only by the single `canvasAndList` image case, now **5** references. Flyover shipped nothing in the 2026-08-30 or 2026-09-06 windows, so the gap is unchanged rather than widened again (still 14 test files, 5 references). PR #333 (`ff89e122`, merged 2026-10-07) replaces the graph-sized connector bitmap with vector paths and updates the Where overview reference; it does not add focus/menu/transition cases. The October 26 inventory has 19 test/support files and five Flyover references: web export, thumbnail, and policy guards were added by #358/#359/#362, and #436 adapts cutsheet variants. PR #444 adds the shared manifest fixture and its namesake test; #415–#444 add TypeScript/browser checks outside this Swift inventory. These do not pin the native focus/menu/transition surfaces. Acceptable for a DEBUG-only tool, and deliberately not a hosting-smoke-test gap (the repo's convention is that an image bundle owns "does this screen render"), so the shape of the fix is more `SnapshotProviding` cases in [`SnapshotTests/`](SnapshotTests) rather than new unit tests — decide which surfaces are worth pinning before adding them wholesale. (audit 2026-08-09; re-verified 2026-09-06)

# Completed issues

- fix [quick-win]: Show capture-load failures with recovery. `Web/src/scripts/previews.ts:18-28` creates images without an error state or retry action. A failed request, or an old open tab after a deployment removes its image path, leaves a broken capture while the surrounding metadata looks valid. Add an accessible failure state with retry/reload guidance and browser tests for 404, interrupted requests, and successful recovery. (agent review 2026-10-26) **Closed: failed previews provide inspector guidance; the inspector offers retry and URL-preserving reload. Browser tests cover HTTP errors, interrupted requests, failed retries, successful recovery, and error-state accessibility.** (closed 2026-10-26)

Add real touch-gesture coverage, automated accessibility scanning, and deterministic request/decoded-image budgets using a representative catalog. Keep timing measurements advisory until a stable runner baseline exists. The current 126 browser regressions passed during review. (agent review 2026-10-26) **Closed: Chromium portrait drives real two-touch input. Chromium and WebKit run axe scans and deterministic thumbnail-request/decoded-pixel guards at desktop, portrait, and landscape sizes. Timing measurements remain advisory.** (closed 2026-10-26)
