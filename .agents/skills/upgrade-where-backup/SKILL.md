# Upgrade a Where backup

Read the root `AGENTS.md`, `Where/AGENTS.md`, and `Where/WhereCore/AGENTS.md`.
Load the `running-tests` skill because verification must run through `./test`.

Run the bundled driver from the repository root:

```bash
ruby .agents/skills/upgrade-where-backup/scripts/upgrade_and_verify.rb INPUT [OUTPUT]
```

`INPUT` may be an unpacked backup directory or ZIP. `OUTPUT` defaults to a
sibling named `<input>-upgraded.zip`. The driver:

1. Reads the source manifest and records the counts that migration must preserve.
2. Creates a temporary input ZIP when necessary.
3. Runs the repository's pinned Ruby and `Where/Tools/upgrade-backup.rb`.
4. Checks ZIP integrity, the current manifest version, required tables, and counts.
5. Generates `Where/WhereCore/Tests/BackupUpgradeVerificationTests.swift` from
   `assets/BackupUpgradeVerificationTests.swift.template`.
6. Runs only that test through `./test`, exercising `BackupService.readArchive(at:)`
   and all referenced asset bytes.
7. Removes the generated test in an `ensure` block and confirms it is gone.

## Safety and recovery

- Never modify or delete the input.
- Do not pass `--force` unless the user explicitly approves replacing the exact
  output path. Without it, an existing output is rejected.
- Expect filesystem approval when the output is outside the workspace.
- If the driver reports a pre-existing generated test, inspect it first. Remove
  it only when its header says it was generated by this skill.
- The upgraded ZIP remains available if Swift verification fails. Diagnose the
  failure; do not represent the backup as verified.
- Use `--keep-test` only for debugging. Remove the generated test before handoff.

## Handoff

Report the output path, source and destination format versions, preserved record
counts, ZIP result, Ruby regression result, Swift production-decoder result, and
whether the repository is clean. Do not expose backup contents in logs or the
response.
