# Repository documentation contracts

## Per-module docs

Every module has `Sources/`, `Tests/`, `README.md`, and `AGENTS.md`; apps also have `Resources/`.
Module groups such as Broadway and Periscope carry the same documentation pair.

- `README.md` owns the overview, public API, usage, and limitations.
- `AGENTS.md` links the README and root contract, then states local boundaries, non-obvious constraints, exceptions, and a testing pointer.
- Group instructions own only shared boundaries. Keep each rule at one owner.
- Omit type inventories, behavior evident from source, generic engineering advice, and repeated ancestor rules.
- State the action and condition. Retain a short consequence only when it prevents a plausible wrong change. Preserve diagnostic signatures, remeasurement conditions, and useful guard links.

Update affected documentation when architecture, public API, conventions, or documented behavior changes.
Update the root contract only when its rules or task routes change.
After adding or renaming instructions, run `./sync-agents --check`.

## Repo-level docs

- [BACKLOG.md](../../BACKLOG.md) owns actionable work in Linear, including evidence and closure rules. Use [todo-triage](../skills/todo-triage/SKILL.md); do not create a local backlog.
- [Plans/](../../Plans/README.md) records selected work. Use [planning](../skills/planning/SKILL.md) for its lifecycle.
- `FLAKY_TESTS.md` is generated by `./flaky`.
- `MODULE_AUDIT.md` is a dated, derived module inventory with verified-clean areas, cross-cutting themes, and Linear links. It contains no independent tasks or copied issue bodies. The weekly triage pass updates Linear first, then the report.
